# HQ estimating 0.6

Previous release verified: main commit cc8f87e37dc339dcc460b1b42a645b7f78af5080 had successful Vercel deployment status and both HQ sales migrations were present. Its estimate flow used external signing and manual acceptance.

This release adds plain-language discovery starters, a WorkForge service pricebook, saveable unpriced drafts, an issue-readiness checklist, provider and client electronic signatures, a private client review page, and Gmail delivery. Both built-in signatures atomically accept the exact issued proposal and invoke the existing fee/project/checklist handoff. External acceptance remains available for agreements signed outside HQ before any built-in signature.

Pricebook: twelve services seeded with no assumed rates. Standard prices may be entered or individual estimates priced by scope. Drafts permit zero rates; issuing rejects zero-value lines. Pricebook changes do not change existing estimates.

Signatures: typed legal name and optional drawn PNG, title, email, explicit consent, timestamp and SHA-256 fingerprint of the frozen customer document. Provider requires HQ write access. Client requires a 64-character random token bound to the recipient email and proposal. Links expire after 30 days or proposal expiry, are explicitly revocable, and stop working for superseded/declined proposals. Tokens travel in URL fragments and POST bodies, avoiding access-log/referrer URL disclosure. Discovery/internal records are omitted from public review. This is bearer-link signing, not independent identity verification. Signature rows cannot be changed through normal authenticated or anonymous API access.

Gmail: Supabase Edge Function validates the signed-in user and HQ membership. Owner/administrator configures a Google web OAuth application, then grants Gmail send and sender-settings scopes. PKCE and one-use expiring state protect authorization. Credentials and refresh tokens are encrypted in Supabase Vault, accessible only through service-role functions. Sender is fixed to estimating@workforgeos.com and checked as a verified Gmail send-as address before every send. Each email requires explicit recipient/message review. Delivery records distinguish sent, failed and unknown; there is no automatic retry of uncertain sends.

Google setup: enable Gmail API; configure consent/test-user availability appropriate to the Workspace account; add the callback displayed under Sales & delivery → Estimate email to the OAuth client's authorized redirect URIs; save that application's client ID/secret in HQ; connect the mailbox with the verified estimating alias. Existing Supabase Google sign-in does not itself authorize Gmail. No additional paid integration is introduced. The callback and email links use the existing canonical WorkForge deployment.
